# 架构调整（2026-09-16）：引入 AgentScope Java 2.x 实现智能体

## 1. 为什么要改

原实现是「手写编排 + Spring AI ChatClient」：智能体的推理-工具循环、工具按固定顺序调用、对话记忆都是业务代码里手写的，
新增一个能力要同时改 `AiServiceImpl`、Agent 类、Tool 类三处，且多轮记忆依赖自研 Redis ChatMemory，与框架能力割裂。

改造后：智能体运行时统一交给 **AgentScope Java 2.x（io.agentscope:agentscope:2.0.3）**，Spring AI 只保留向量能力（Embedding + Milvus VectorStore），通过工具形式暴露给智能体。

## 2. 新分层

```
Controller
   └── AntiFraudOrchestratorService   状态机 / 安全护栏 / 业务落库（不含 LLM 调用细节）
          ├── RouterAgent    ─┐
          ├── AnalysisAgent  ─┼─► AgentScope ReActAgent（推理-工具循环 + 结构化输出）
          ├── ActionAgent    ─┤
          └── ChatAgent      ─┘
                 │  Toolkit（@Tool 工具：号码画像/黑名单/知识库/关停/通知）
                 │  AgentStateStore（会话上下文持久化，替代自研 Redis ChatMemory）
                 └── Model（OpenAI 兼容协议：阿里云百炼 compatible-mode）
```

| 组件 | 说明 |
|---|---|
| `config/AgentScopeConfig` | 模型（OpenAI 兼容端点，注意 base-url 需要带 `/v1`）+ `JsonFileAgentStateStore`（多副本可换 Redis/MySQL 实现） |
| `config/AgentScopeAgentConfig` | 按「模型 + 工具 + 提示词 + 状态存储」装配 4 个 `ReActAgent`：router / analysis / action / chat |
| `service/agent/RouterAgent` | 意图识别 + 号码槽位提取，纯分类无工具，结构化输出 `RouterResult` |
| `service/agent/AnalysisAgent` | **真正的 ReAct**：模型自主决定调用哪些取证工具（画像/黑名单/知识库），再输出 `RiskAssessmentReport` |
| `service/agent/ActionAgent` | 模型调用关停/通知工具后回填 `ActionDecision`；工单落库仍由业务层单点写入，避免双写与单号冲突 |
| `service/agent/ChatAgent` | UNKNOWN 意图兜底问答，多轮记忆由 `AgentState` 承载 |
| `service/tool/*` | `@Tool`/`@ToolParam` 迁移到 AgentScope 注解；`RuntimeContext` 注入用于审计上下文回填与证据链收集（`EvidenceBundle`） |
| `resources/prompts/*.st` | 4 份系统提示词（router/analysis/action/chat），去掉旧模板占位符 |

## 3. 关键约定

1. **结构化输出**：`agent.call(msgs, Xxx.class, ctx).block()` + `msg.getStructuredData(Xxx.class)`；
   兼容端点不支持 `json_schema` 时框架自动降级为「合成工具」路径，调用方代码不变。
2. **会话隔离**：每次调用传 `RuntimeContext.builder().sessionId(sessionId).userId(userId)`，
   同一 (userId, sessionId) 自动复用 AgentState，实现多轮连续；`chat()` 会复用用户最近一次未结束的会话。
3. **线程模型**：工具在 Reactor 线程回调，请求线程 ThreadLocal 不可见 → 工具内通过 `RuntimeContext`
   回填 `AgentContextHolder`（保证 `t_tool_call_log` 审计链路不丢），并把结果写入 `EvidenceBundle` 形成证据链。
4. **降级策略不变**：结构化结果缺失时按「中风险 + 转人工」兜底；高风险未开启自动关停时只建 PENDING 工单。
5. **Spring AI 保留范围**：仅 `spring-ai-starter-model-openai`(Embedding) + `spring-ai-starter-vector-store-milvus`，
   已删除 `AiService`/`AiServiceImpl`/`AiConfig`/`RedisChatMemoryRepository`/`PlaceholderTemplateRenderer`。
